---
title: Connection And Proxy Lifecycle
description: Observe shared Nexus connections and recreate session-bound resources.
---

A `Connection` is a shared session handle, not a caller-owned lease. Dropping a
connection, collection, or root service proxy does not close the session.

## Connection Lifetime

```ts
const connection = await nexus.connect({ target });

const stop = connection.onDisconnected((reason) => {
  recordDisconnect(connection.id, reason);
});

// Explicitly ends the shared session for every local user.
connection.disconnect();
stop();
```

`connection.status` is `"connected"` or `"disconnected"`. Disconnect is
terminal: a later connection has a new identity, and existing proxies and refs
never retarget or revive. `onDisconnected` notifies each subscription at most
once, including when registered after termination. `disconnect()` is idempotent
and does not wait for a remote business acknowledgement.

## Observe Connections

Use `onConnect` to receive each existing and future ready session once. It does
not dial, wait for a Token, or retry application initialization.

```ts
const stop = nexus.onConnect(matchesReadyContent, (connection) => {
  void initializeSource(connection).catch(reportSourceFailure);
});
```

The listener may be registered before bootstrap. Stopping it only ends future
notifications; it neither disconnects sessions nor cancels work already started.

## Observe Identity

`connection.subscribeIdentity(listener)` immediately receives the remote full
`ContextMeta`, then every later validated complete update for that session:

```ts
let wasReady = false;

const stop = connection.subscribeIdentity((meta) => {
  const becameReady = !wasReady && meta.pageReady;
  wasReady = meta.pageReady;
  if (becameReady) void initializeSource(connection).catch(reportSourceFailure);
});
```

It does not filter fields, deduplicate equal values, or invoke returned cleanup
functions. A disconnected connection does not issue an identity update; observe
that transition through `onDisconnected`.

The `where` passed to `connect` is an acquisition filter, not a retained call
constraint. Identity changes alone do not invalidate ordinary calls. State handles
separately observe their selection predicate and can become `stale`; authorization
policy may also close a session or reject a call.

## Replacement

Service proxies, refs, and callback handles are session-bound. After a reload,
daemon restart, or disconnect, reconnect and get a new proxy. A
`ConnectionCollection` is similarly fixed: it does not add new sessions, remove
disconnected ones, or replace members after reconnect.

## Reserved Proxy Names

The root proxy suppresses only `then`, so it is not accidentally awaited. Root
services may still expose business methods named `catch` or `finally`. On a
nested property path, `then`, `catch`, `finally`, and `connection` are reserved
for lazy-call consumption and local provenance. Do not use those names for
nested remote business members; use a different service method or access the
member through a non-reserved path.
