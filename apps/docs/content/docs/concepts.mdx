Nexus connects isolated JavaScript contexts through typed services. The examples
below use a document service; runtime setup is covered in the
[quick start](/nexus/docs/getting-started/).

## Context And Runtime

A **context** is an isolated JavaScript environment, such as a page or process.
A **Nexus instance** is the runtime that owns local providers, connections, and
communication resources. The application creates the contexts; an adapter supplies
the transport that connects them.

```ts
import { Nexus } from "@nexus-js/core";

const app = new Nexus(); // Configure its endpoint before connecting.
```

Both contexts have their own runtime. Either side can provide services and call
the other over the same bidirectional connection.

## Service Contract And Token

A **service contract** is the TypeScript interface describing the capability.
A **Token** associates that type with a stable runtime service ID:

```ts title="shared.ts"
import { Token } from "@nexus-js/core";

export interface DocumentService {
  summarize(id: string): Promise<string>;
}

export const DocumentToken = new Token<DocumentService>("example:documents");
```

Both sides import this shared definition. `DocumentService` supplies compile-time
types; `"example:documents"` identifies the service at runtime. The type parameter
is not a runtime schema validator. A Token contains no address, connection, or
implementation, and the same Token can be provided by multiple contexts.

## Provider

A **provider** registers a local implementation under a Token on its owning runtime:

```ts
app.provide(DocumentToken, {
  async summarize(id) {
    return `Summary of ${id}`;
  },
});
```

Other contexts access this object through a proxy; they do not receive a copy of
the implementation. See [Services](/nexus/docs/services/) for object and class providers.

## Connection And Proxy

A **Connection** represents one ready session with a peer. A **service proxy**
represents access to one of that peer's services:

```ts
const connection = await app.connect({ target });
const documents = connection.get(DocumentToken);
const summary = await documents.summarize("intro");
```

The adapter-specific `target` answers **where to connect**; the Token answers
**which service to use**. `get` checks the peer's current service catalog and
returns a proxy synchronously. It does not wait for a future provider.

Proxy operations are asynchronous and lazy: declaring `documents.summarize(...)`
alone sends nothing; consuming the result with `await` starts the call.
See [Connections](/nexus/docs/connections/) and [Remote calls](/nexus/docs/remote-calls/).

## Values, Callbacks, And Remote Resources

Ordinary supported values travel as serialized data. To interact with behavior
that stays in the other context, Nexus uses references:

- A **callback** refers to a function in its original context. Its closure stays
  there, so it can access the local state it captured.
- A **remote resource** refers to an object explicitly marked with `ref(...)`.
  The object stays with its owner; the consumer calls its methods remotely.

For a document service exposing a `watch` method, this lets one operation connect
a local callback with a remote subscription:

```ts
const subscription = await documents.watch("intro", (change) =>
  panel.apply(change),
);
await subscription.stop(); // Invoke the remote business operation.
Nexus.release(subscription); // Give up this reference.
```

`watch` extends the basic contract above. Its provider returns a subscription
object through `app.ref(subscription)` and declares a `RefWrapper<Subscription>`
return type. See [Callbacks](/nexus/docs/callbacks/) and
[Remote resources](/nexus/docs/remote-resources/) for the complete contract and ownership.

## Session Lifetime

Service proxies, callbacks, and remote resources remain bound to their connection.
After disconnect, acquire a new connection and fresh handles. Reconnection does
not revive old handles or replay business operations.

Stopping a business operation, releasing a reference, and disconnecting the shared
session are separate actions. See [Connection lifecycle](/nexus/docs/proxy-lifecycle/)
for cleanup, and [Errors and timeouts](/nexus/docs/error-handling/) for handling
failures at connection, service acquisition, and call boundaries.
