**Nexus Relay** lets callers use a service through an intermediate context. The
application registers a forwarding entry for selected Tokens on that context's
Nexus instance. The caller still connects and gets a service proxy; the actual
provider still implements the shared contract.

The background selects the content script. Relay forwards calls, results,
callbacks, and remote references without combining the two connections into a
single session.

## Register A Forwarding Entry [#register-a-bridge]

These examples reuse `DocumentToken` and `DocumentService` from
[Getting Started](/nexus/docs/getting-started/). All three contexts import the
same contract. The content script provides the service:

```ts title="content.ts"
import { usingContentScript } from "@nexus-js/chrome";
import { DocumentToken, type DocumentService } from "./shared";

const contentNexus = usingContentScript();
const documents: DocumentService = {
  async summarize(documentId) {
    return `Summary of ${documentId}`;
  },
};

contentNexus.provide(DocumentToken, documents);
```

Configure the background instance and register the Relay in its startup module. `selectedDocument` is an application-selected destination containing `tabId` and `documentId`, obtained through Chrome APIs or the application's page registry:

```ts title="background.ts"
import { Nexus } from "@nexus-js/core";
import { chromeTarget, usingBackgroundScript } from "@nexus-js/chrome";
import { DocumentToken } from "./shared";
import { selectedDocument } from "./selection";

const backgroundNexus = usingBackgroundScript();

const relay = Nexus.relay({
  from: backgroundNexus,
  to: {
    nexus: backgroundNexus,
    target: chromeTarget.contentDocument(selectedDocument),
  },
  services: [DocumentToken],
});
```

- `from`: the local instance that offers the forwarding entry to callers.
- `to.nexus`: the local instance that connects to the actual provider. It is the same instance here; a bridge between adapters can use another instance in the same context.
- `to.target`: the exact connection target for that instance.
- `services`: the shared Tokens to forward.

Registration returns a `RelayHandle` synchronously. An upstream connection is acquired when a call first needs it. Successful registration makes the forwarding entry available; it does not mean the destination service is online. Use `Nexus.safeRelay()` to handle registration errors as a `Result`.

Register synchronously in the startup module, as above, or dynamically after `await backgroundNexus.ready()`. On one instance, a Token can belong to either a local service or a Relay entry. A conflict rejects the entire registration batch.

## Call Through Relay [#call-through-relay]

The popup connects to the background and gets the same Token:

```ts title="popup.ts"
import { chromeTarget, usingPopup } from "@nexus-js/chrome";
import { DocumentToken } from "./shared";

const popupNexus = usingPopup();
const connection = await popupNexus.connect({
  target: chromeTarget.background(),
});
const documents = connection.get(DocumentToken);

const summary = await documents.summarize("intro");
```

The caller does not need to connect to the content script. `get` creates a
proxy from the background's service catalog; the first consumed call starts
upstream acquisition:

Callbacks and object references returned through `ref()` can also cross the
bridge; they remain owned by the context where they were created. See
[Callbacks](/nexus/docs/callbacks/) and
[Remote Resources](/nexus/docs/remote-resources/) for complete examples.

## Select A Destination And Chain Relays [#keep-routing-in-the-application]

`to.target` and `to.where` follow ordinary [connection acquisition](/nexus/docs/connections/) rules:

- With a `target`, Nexus can connect to that destination. If `where` is also supplied, the connection must satisfy it.
- Without a `target`, acquisition waits for exactly one matching existing session. It does not discover providers.
- `where(contextMeta, connectionMeta)` filters peer identity and local connection facts. Authorization remains in `policy.canConnect` and `policy.canCall`.

A Relay registration captures its destination selection. To forward to another page after a page change, dispose the registration and create one with the new target.

For multiple hops, configure each intermediate context separately. On a path
`A → B → C → D`, B forwards the service to C, and C forwards it to D. Each
hop selects only its next destination. The Token identifies the contract, not
a path or an address.

## Manage A Group Of Resources Independently [#resource-scopes]

Ordinary `connection.get(Token)` calls use a default resource scope managed by Nexus. When several panels or tasks share a connection and one group of resources needs its own lifetime, create an explicit `ResourceScope`:

```ts
const scope = connection.createScope(DocumentToken);
const documents = connection.get(DocumentToken, { scope });

try {
  const summary = await documents.summarize("intro");
  console.log(summary);
} finally {
  scope.close();
}
```

A scope belongs to the Connection and Token that created it. It groups calls,
callbacks, and remote references. Relay pairs that scope with an upstream
scope, but the two Connections remain shared:

<Mermaid
  caption="Each caller has its own scope across the bridge, even when the background reuses the same upstream Connection."
  chart={`flowchart LR
    A["Popup A scope"] --> BI_A["Relay inbound A"] --> BO_A["Relay outbound A"] --> CA["Content scope A"]
    B["Popup B scope"] --> BI_B["Relay inbound B"] --> BO_B["Relay outbound B"] --> CB["Content scope B"]
    BO_A -.-> SHARED["Shared background–content Connection"]
    BO_B -.-> SHARED`}
/>

Closing A's scope invalidates only A's calls, callbacks, and refs. B's scope
and the shared Connection remain available. A scope cannot be passed to a
different Connection or Token.

`close()` is idempotent and is also available through `[Symbol.dispose]()`. Read `closed` to check its state, or use `onClosed(listener)` to observe termination. A listener added after closure runs immediately.

Closing a scope does not call business methods such as `stop()` or `unsubscribe()`, or undo completed operations. When business cleanup is needed, invoke the appropriate method before releasing the reference or closing the scope.

### Provider Cleanup [#provider-lifecycle]

A service can use `SERVICE_INVOKE_START` from `ServiceInvocationHooks` to access `context.scope`, then use `scope.onClosed(...)` to clean up its own listeners or other business resources. Register cleanup when the resource is created rather than adding the same listener on every ordinary call.

If an async method needs its invocation context, return `context` from the start hook. Nexus appends it to the local method's arguments as a `ServiceInvocationContext`. This argument is not part of the remote service contract. Keep it in a local variable for that invocation instead of sharing a mutable "current scope" across concurrent calls.

## Forward Nexus State [#state-and-relay]

Include the shared StoreToken in `services` to forward a Store. The caller uses `connectNexusStore()` as usual, targeting the context that hosts the Relay:

```ts
import { connectNexusStore } from "@nexus-js/core/state";
import { chromeTarget } from "@nexus-js/chrome";
import { WorkspaceStoreToken } from "./shared";

// The background Relay includes WorkspaceStoreToken in services.
const workspace = await connectNexusStore(popupNexus, WorkspaceStoreToken, {
  target: chromeTarget.background(),
});

try {
  console.log(workspace.getState());
  await waitUntilPopupCloses();
} finally {
  workspace.destroy();
}
```

`waitUntilPopupCloses()` represents the application's own UI lifecycle logic. Each remote Store subscription automatically owns an independent scope; destroying one mirror cleans up its subscription without affecting other callers' mirrors. See [Nexus State](/nexus/docs/state/) for reads, actions, and React usage.

## Stop Forwarding And Handle Disconnects [#lifecycle]

When the background no longer needs the forwarding entry, dispose its registration:

```ts
relay.dispose();
```

This removes the service entries owned by that registration and closes their
resource scopes. Shared connections remain open.

When a connection on the path breaks, its dependent scopes end. Existing refs, callbacks, and Store mirrors cannot be reused. In-flight calls are not replayed automatically because the service may already have performed the operation.

- **The caller's connection to Relay is still available:** a later root service call using the default scope can acquire an upstream connection and establish a new scope.
- **The caller's own connection has closed:** call `connect()` again and get a fresh service proxy.
- **The caller used an explicit scope or State mirror:** create a new scope or call `connectNexusStore()` again to obtain fresh handles and a state baseline.

See [Connection Lifecycle](/nexus/docs/proxy-lifecycle/) and [State Lifecycle And Errors](/nexus/docs/state/lifecycle-and-errors/) for further lifecycle rules.
